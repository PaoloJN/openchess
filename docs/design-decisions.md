# Design Decisions

Why the current OpenChess hardware looks this way.

## Split The Hardware Into Three Boards

The old integrated-board direction put the matrix, controller, power, status
LEDs, and controls onto one large PCB. The current design separates them:

- `hardware-board`: passive matrix with Hall sensors and LEDs
- `hardware-controller`: ESP32, power, scan drivers, connector logic
- `hardware-control-panel`: side-mounted buttons and status LEDs

This reduces layout risk, makes testing cheaper, and lets the control panel be
mounted wherever the enclosure needs it.

## Keep A3144 TO-92 Hall Sensors For The First Prototype

A3144 sensors are cheap, available in bulk, hand-solderable, and known to work
in similar chess-board projects. SMD Hall sensors may be cleaner later, but TO-92
is lower risk for the first physical prototype.

## Keep WS2812B 5050 LEDs

WS2812B LEDs reduce LED wiring to one data chain and give per-corner RGB state.
The 9x9 corner layout is part of the desired visual style. The schematic now
uses 81 LEDs, 100nF per LED, row bulk caps, and a `+5V_LED` entry cap.

## Move Row Pullups To The Controller

A3144 outputs are open-collector. Pulling `S0..S7` up to `+3V3` on the
controller keeps ESP32 GPIOs safe and keeps the matrix board passive.

## Use A Dedicated Control Panel Board

Status LEDs and buttons should not live on the matrix board. A small cable panel
is easier to mount on the enclosure side and can change mechanically without
forcing a matrix-board respin.

## Keep Schematic Generation Scripted

Repetitive schematic content is generated by scripts. Each board follows the
same pattern: `config.py`, `geometry.py`, `parts.py`, chunk scripts, and
`99_assemble.py`. This makes the design easier to regenerate, review, and later
variant for a 4x4 prototype.
